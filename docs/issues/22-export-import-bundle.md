# Title

`.inkstory` export/import: user-owned backups over a hostile-input-hardened parser

## Summary

Implement the DESIGN §7.3 bundle format: zip export of selected characters/books and an
import path treated as a hostile-input boundary (B3) with the full cap/validation/
re-encode battery and an all-or-nothing commit.

## Context

Export is the durability story (ADR-005 #3, iOS eviction mitigation); import is the
single most exposed parser surface in the product (DESIGN §10.2 B3, §10.5 abuse case:
crafted bundle shared between strangers). Every §10.3 B3 control lands here.

## Scope

`src/exchange/`: `export.ts`, `import.ts`, `bundleSchema.ts` (path grammar + manifest),
portable import/export DTO schemas and blob/Drawing reconstruction helpers,
settings-screen UI (export selector, import flow with preview + report), malicious
fixture corpus under `tests/fixtures/bundles/`.

## Detailed Requirements

1. Export: user selects characters and/or books (books auto-include their characters);
   stream-build zip (fflate) with exactly the §7.3 layout; images re-used as stored
   (already metadata-free per ADR-005); `manifest.json` first entry. Output via
   `showSaveFilePicker` where available, else anchor-download; filename
   `inkstory-YYYYMMDD.inkstory`.
2. Import pipeline (order matters, fail fast, never partial-write):
   a. file size ≤256 MiB before reading;
   b. central directory parse: entries ≤1000; every path must match the §7.3 whitelist
      grammar `^(manifest\.json|characters/<uuid>/(character\.json|texture\.png|thumb\.png)|books/<uuid>/(book\.json|audio/<uuid>\.bin))$`
      — anything else (traversal, absolute, nested zip, unknown file) → reject;
   c. per-entry declared uncompressed size ≤64 MiB and Σ ≤512 MiB; streaming inflate
      aborts past declared size (ratio-bomb guard);
   d. `manifest.json` via `zod.strict()`; `formatVersion > 1` → localized "update
      inkstory" refusal;
   e. JSON docs via strict portable bundle DTO schemas, not raw storage schemas. DTOs
      intentionally omit storage-only blob ids and Drawing rows; import reconstructs
      fresh Drawing/blob records for texture, thumbnail, and narration files, then maps
      them into issue-04 storage schemas before commit. Cross-references are verified
      after reconstruction (every referenced file present, no dangling ids);
   f. every image **decoded then re-encoded** via canvas (dims ≤4096², else reject) —
      output replaces input bytes; audio entries stored as opaque blobs ≤20 MiB with
      mime from book.json. Validate audio MIME by parsing the media type and allowing the
      safe containers `audio/mp4`, `audio/webm`, `audio/ogg`, `audio/mpeg` plus recorder
      parameters such as `;codecs=opus`; reject unknown media types or unsafe parameters;
   g. id collision policy: imported entities get **fresh UUIDs** (remapped
      consistently across the bundle) — imports never overwrite existing data;
   h. commit: single Dexie transaction; any failure → nothing written + per-entry
      error report (path + reason) rendered in the UI.
3. Preview step before commit: "will add: N characters, M books (titles)" list from
   validated metadata; user confirms; then commit runs.
4. Round-trip guarantee: export→import on a second profile yields functionally
   identical characters/books (new ids).
5. Malicious corpus (checked-in, generated by a script with comments):
   path-traversal name, extra top-level file, nested zip, ratio bomb (small zip →
   >64 MiB entry), oversized image dims, NaN in rig JSON, extra JSON keys, dangling
   audio ref, mime spoof (exe bytes as .bin with image mime in json), formatVersion 99.
   Each must be rejected with the mapped reason and zero DB writes.

## Acceptance Criteria

- Round-trip test green (fake-indexeddb): golden character + 3-page narrated book.
- DTO reconstruction test green: exported bundle JSON without storage blob ids imports
  into schema-valid Drawing, Blob, Character, Book, and Page rows with fresh UUIDs.
- Every malicious fixture rejected with its specific reason; DB row-count unchanged
  (asserted before/after).
- Import of a 200 MB synthetic bundle stays responsive (progress events; main thread
  unblocked — inflate in a worker) and peak memory bounded (streaming, no full-buffer
  duplicate) — measured note in PR.
- Fresh-UUID remap verified: importing the same bundle twice yields two independent
  copies.

## Validation

`pnpm test src/exchange` incl. corpus; manual: export from Chrome, import on Safari
(and vice versa) — matrix note in PR (audio codec caveat surfaces here per
docs/research/03).

## Dependencies

04, 05.

## Non-goals

Cloud sync/share links (v2+), selective merge/dedup UI (v1 = always-new-copies),
transcoding audio.
